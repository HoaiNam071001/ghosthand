# 61. Dùng AI gọn hơn – ít token, ít lỗi môi trường

- [ ] **61. Dùng AI gọn hơn** *(người dùng yêu cầu 2026-11-03, từ kinh nghiệm AI tự thử ~90 mẫu + kiểm tra tay qua MCP)* – bớt token mỗi phiên, chạy thử hàng loạt không cần AI, báo lỗi môi trường trước khi chạy, tránh AI đụng nhầm cửa sổ / để lại file rác.
  - [x] M1. Rút gọn trạng thái tự chèn đầu phiên (`scripts/session-status.sh`): mục *Đang làm* ở `README.md` đang liệt kê chi tiết mọi bước (hàng nghìn chữ, tốn token mọi phiên) → hook chỉ in bước đang làm (tên + link + một dòng), bước tiếp theo, số việc chờ thử tay, git. Chi tiết dời về file bước / bảng tiến độ; `wrap-up` ghi *Trạng thái hiện tại* ngắn (giới hạn độ dài – `check-docs.py` cảnh báo khi quá dài)
  - *Làm M1 (2026-11-03):* mục *Trạng thái hiện tại* ở `README.md` viết lại 4 dòng (đang làm / xong code chờ thử tay chỉ ghi số bước / tiếp theo / cập nhật lần cuối một ý) – từ ~9 200 còn ~520 ký tự; hook giữ nguyên (in nguyên mục); `check-docs.py` cảnh báo khi mục > 1500 ký tự; skill `wrap-up` ghi quy ước.
  - [x] M2. Chạy nhiều kịch bản một lượt: CLI `ghosthand test <file|thư mục|mẫu…>` (chạy lần lượt, `--set`, `--preset`, tiếp tục khi lỗi) + tool MCP cùng việc → bảng gọn mỗi dòng: tên, qua / lỗi, mã lỗi, node lỗi, thời gian; chi tiết chỉ cho dòng lỗi. Thay script shell tự viết lúc thử (`runall.sh`)
  - *Làm M2 (2026-11-04):* người dùng chốt – đích `mau:<id>` + `--samples` (bỏ mẫu web thật / `manual`, `--all` lấy cả, `--level N`); MCP hỏi một lần cả lượt; không ghi Lịch sử. Vòng chạy ở app (`internal/batch` ← `app/batchrun.go`), dùng chung API `/batch` (CLI `ghosthand test`, hỏi tiến độ 0,5 s) và tool `run_batch` (chạy nền, gọi lại với `batchId`; `stop_run batchId`). Meta mẫu thêm `manual` (9 mẫu: cần đăng nhập / bí mật / app riêng / nhập giờ / chỉ Windows). `--set` chỉ áp cho kịch bản có input đó; `--preset` kịch bản không có bộ thì dùng mặc định. Người dùng bấm F8 hoặc tự Chạy giữa lượt → dừng cả lượt. Ngân sách `tools/list` 30 000 → 31 200 (run_batch ~1 KB đã viết gọn). Thử tay → [checks.md](../checks.md).
  - [ ] M3. Kiểm tra môi trường trước khi chạy: dò sẵn chuyện hay làm kịch bản lỗi giữa chừng không do kịch bản – Chrome bật *hỏi nơi lưu tệp*, cửa sổ trình duyệt quá nhỏ so với kịch bản cần, hộp thoại lạ đang mở (Lưu tệp, cấp quyền), thiếu quyền Accessibility / Screen Recording. Gộp với `check_permissions`; trả cảnh báo kèm cách sửa, MCP `run_script` trả trong kết quả (không chặn chạy)
  - [x] M4. `browserNorm` (Đặt trình duyệt chuẩn) không ghi trình duyệt / tab đích thì hiện đang lấy trình duyệt ở trước → AI thử đã đổi cỡ cửa sổ Cốc Cốc của người dùng. Bắt buộc chọn đích (trình duyệt + tab theo URL / tiêu đề) khi bật *đặt cỡ cửa sổ*: kiểm tra kịch bản báo lỗi, inspector đánh dấu ô thiếu, guide AI ghi rõ
  - *Làm M4 (2026-11-04):* đích hợp lệ khi bật `normSize` = `tabFrom`, hoặc `browser` + `tab` (chỉ chọn trình duyệt vẫn lấy tab đang hiện – chưa đủ). Bật zoom / thoát toàn màn hình / popup không bắt chọn đích (không đổi cỡ cửa sổ). Go `validateNorm` (lỗi trường `browser` / `tab`) khớp TS `normTargetMissing` (`flow/browserTab.ts`, cảnh báo thẻ + dòng đỏ inspector); mô tả `get_step_types` + ví dụ có `browser` + `tab`; trang Hướng dẫn thêm mẹo. Kiểm tra tay → [checks.md](../checks.md).
  - [ ] M5. Kịch bản tạm AI tạo khi thử (tên "Thử …", tạo qua `create_script` rồi bỏ): đánh dấu kịch bản do AI tạo để thử (cờ trong file hoặc thư mục con), tự dọn sau N ngày không mở (Cài đặt, mặc định 7), danh sách kịch bản ẩn / gom nhóm riêng; primer MCP nhắc dùng `run_script script=…` trước
  - Chuẩn bị cho MCP: M2 tool mới (annotations, nhóm tool, giữ `budget_test.go`); M3 cảnh báo gọn trong `run_script`; M4 sửa `get_step_types type=browserNorm`; M5 primer.
  - Kiểm tra tay: phiên Claude mới – đoạn trạng thái tự chèn ngắn (≤ ~15 dòng); `ghosthand test` thư mục mẫu ra bảng đúng; bật *hỏi nơi lưu* ở Chrome → chạy mẫu tải tệp thấy cảnh báo trước; `browserNorm` không chọn đích bị báo lỗi kiểm tra; kịch bản "Thử …" cũ tự dọn.
  - Xong khi: M1–M5 xong code + kiểm tra tay.
