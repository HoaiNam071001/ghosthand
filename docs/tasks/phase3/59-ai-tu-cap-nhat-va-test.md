# 59. AI tự cập nhật app rồi test qua MCP

- [ ] **59. AI tự cập nhật + test** *(người dùng yêu cầu 2026-11-01: AI vừa dev xong → release / cài bản mới → dùng MCP test sản phẩm sau thay đổi luôn)* – khép vòng dev → cài → thử thật mà người dùng không phải tự build / cài / mở lại app.
  - **Đã chốt (2026-11-01):** cả hai đường – (1) lúc dev: build + cài bản local đè app đang cài, nhanh, không tạo Release; (2) khi phát hành: tool MCP `update_app` cài bản Release chính thức rồi test lại. Quyền `update_app` theo mức AI ở Cài đặt (*Tự chạy* = tự cài, thấp hơn = hộp hỏi như khi AI chạy kịch bản).
  - Nền có sẵn: `internal/update` (Check / PickAsset / Download + sha256 / Install, script nền chờ app thoát → thay → mở lại; từ chối khi đang chạy / kịch bản chưa lưu), `scripts/mac-build.sh` (ký "Ghosthand Dev" – giữ quyền Accessibility / Screen Recording qua các bản build).
  - [ ] U1. Thông tin bản đang chạy: số phiên bản + commit git + giờ build gắn lúc build (`-ldflags`, bản dev = `dev-<sha>`); MCP tool `app_info` (version, commit, startedAt, đường dẫn app) – AI kiểm đúng bản vừa cài đang chạy; tab Giới thiệu hiện commit
  - [ ] U2. Thoát êm từ ngoài: API local `POST /quit` (token như các route khác) + CLI `ghosthand quit` – lưu nháp, từ chối khi đang chạy kịch bản (trả lỗi rõ); dùng cho U3
  - [ ] U3. `scripts/dev-install.sh` (macOS; `make dev-install`): build + ký như `mac-build.sh` (không làm dmg) → `ghosthand quit` → chờ thoát → thay `/Applications/Ghosthand.app` (giữ bundle ID + chữ ký để không mất quyền; lỗi thì trả bản cũ như `MacSwapScript`) → mở lại nền (`--background`) → chờ `/health` trả đúng commit. Windows: bản portable đè exe – làm trên máy Windows
  - [ ] U4. Proxy `ghosthand --mcp` sống qua lần app mở lại: POST /mcp lỗi nối / app đang thoát → chờ app lên lại (≤ 30 s, đọc lại cổng + token) rồi gửi lại thay vì trả lỗi cho client AI
  - [ ] U5. MCP `update_app`: `check` (bản mới nhất, ghi chú) | `install` – chỉ Release của repo, kiểm sha256 (dùng `internal/update`), quyền theo mức AI + hộp hỏi; trả ngay "đang cập nhật, app sẽ mở lại" → AI gọi `app_info` sau khi app lên. Annotations: destructive + openWorld
  - [ ] U6. Skill dự án `test-after-change` (+ nhắc trong `wrap-up`): `make dev-install` → `app_info` đúng commit → chạy các mẫu liên quan tới phần vừa sửa qua MCP (`run_script` mẫu ở `internal/samples` / kịch bản tạm) → báo kết quả + ảnh lỗi; sửa xong lặp lại. Không chạy mẫu đụng tài khoản thật (gửi tin, thanh toán) khi người dùng chưa bảo
  - U5 = đúng nút *Cập nhật ngay* ở tab Giới thiệu (cùng code, bản Release cũng ký "Ghosthand Dev" qua `mac-build.sh`) – không thêm rủi ro. Lưu ý riêng U3: bản dev phải ký qua `mac-build.sh` như bản Release, bỏ bước ký thì macOS mất quyền Accessibility / Screen Recording.
  - Chuẩn bị cho MCP: tool mới `app_info`, `update_app` – annotations, nhóm tool ở Cài đặt MCP, primer ngắn, giữ `budget_test.go`.
  - Kiểm tra tay: sửa một chữ ở UI → AI chạy `make dev-install` → app tự mở lại, `app_info` đúng commit, quyền Accessibility còn nguyên, AI chạy được mẫu qua MCP ngay; tạo Release thử → `update_app install` ở mức *Soạn + chạy (hỏi)* hiện hộp hỏi, đồng ý → app cập nhật + mở lại, phiên MCP của AI vẫn dùng tiếp.
  - Xong khi: U1–U4 + U6 xong code trên macOS (vòng dev); U5 sau.
