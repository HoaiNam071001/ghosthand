# 55. Kết nối MCP server khác + node tuỳ chỉnh từ tool MCP

- [ ] **55. MCP client + node tuỳ chỉnh** *(người dùng yêu cầu 2026-10-28: app kết nối tới các MCP server khác, tạo node tuỳ chỉnh từ tool của chúng)*
  - **Gộp / thay:** thay mục *Node Gọi tool MCP* của [31d](31-mcp-ai.md) (làm ở đây); bước [54](54-dong-bo-cloud.md) C9 (backend MCP của đồng bộ cloud) dùng lại client của bước này.
  - **Đã chốt với người dùng (2026-10-28):** (1) **một loại node chung `mcpTool`** trong engine + **node tuỳ chỉnh = mẫu lưu sẵn** của một tool (tên, icon, nhóm, form sinh từ `inputSchema`) – không tạo loại node động, vì model Go là nguồn chuẩn và kịch bản phải mở được ở máy chưa cài server; (2) hỗ trợ **stdio, HTTP/SSE từ xa, và thư viện server gợi ý**; (3) hỏi quyền **theo server + tool**, tool ghi / xoá / mở ra ngoài luôn hỏi.
  - **Rủi ro:** server stdio chạy code tuỳ ý trên máy (như node *Chạy lệnh* – phải được người dùng đồng ý theo nội dung lệnh); tiến trình con treo / rò (dọn khi đóng app, khi lỗi); tool trả nội dung chứa lệnh giả (prompt injection) → chỉ là dữ liệu; kịch bản gọi server chưa kết nối ở máy khác; `inputSchema` phức tạp (oneOf, lồng sâu) không dựng form được → rơi về ô JSON; secret (token, biến môi trường) không được vào file kịch bản.
  - [x] M0. `internal/mcpclient`: kết nối stdio (lệnh + args + env) và HTTP/SSE (URL + header Bearer) bằng SDK Go; `Client` interface (`ListTools`, `CallTool`, `Close`) + bản giả `mcpclienttest`; quản lý vòng đời tiến trình (khởi động lười, dọn khi thoát, hết giờ, chạy lại khi chết)
    - Xong code (2026-10-28): `mcpclient.Config` / `Client` / `Manager` (nối lười, dùng lại, nối lại khi đổi cấu hình hoặc lỗi giao thức, `CloseAll` khi thoát), stdio ẩn cửa sổ console trên Windows, HTTP dùng streamable + header; bản giả `mcpclienttest` = server SDK chạy trong bộ nhớ. Lỗi kết nối / giao thức **không tự gọi lại tool** (tool ghi có thể đã chạy). Còn nối `Manager.CloseAll` vào lúc app thoát (làm ở M1)
  - [x] M1. Cấu hình server: `Settings.MCPServers` (id, tên, kiểu, lệnh / URL, env / header **chỉ nhận `{{secret.*}}`**, bật / tắt); trạng thái kết nối + danh sách tool (cache, nút Tải lại); lỗi có cấu trúc (không chạy được lệnh, hết giờ, auth)
    - Xong code (2026-10-29): `store.MCPServer` (`Check`: env / header phải có `{{secret.*}}`), `Manager.Refresh` / `StatusOf` / `Forget` (`mcpclient/status.go`, lỗi che bí mật bằng `secrets.Redact`), method `App.*MCPServer` (`mcpserversapi.go`), `CloseAll` trong `shutdown`. UI ở M8.
  - [x] M2. Quyền: lần đầu mỗi server hỏi đồng ý (hiện lệnh / URL đầy đủ, ghi nhớ theo hash cấu hình – đổi lệnh thì hỏi lại); từng tool: dựa `annotations` (`readOnlyHint` / `destructiveHint` / `openWorldHint`) – chỉ đọc chạy luôn sau khi server được duyệt, còn lại hỏi mỗi lần hoặc "luôn cho tool này"; chung hộp hỏi với 22 / `dangerconsent`
    - Xong code (2026-10-29): `store/mcpconsent.go` (`mcp-consent.json`: dấu vân tay `MCPServer.Fingerprint` – lệnh / URL / tham số / tên env + header, không gồm giá trị bí mật; `MCPServerTrusted`, `TrustMCPServer`, `AlwaysAllowMCPTool`), `mcpclient.Decide` (server chưa duyệt → hỏi; chỉ đọc → chạy; còn lại → hỏi hoặc "luôn cho tool này"), `mcpgate.go` (`mcpCall` – đường duy nhất gọi tool, cả `RefreshMCPServer` lần đầu cũng hỏi; event `mcp:ask` → `MCPAskDialog` → `AnswerMCP`). Hộp hỏi riêng cho MCP (nội dung khác `AIRunDialog`) nhưng cùng khuôn + cùng kiểu event / hết giờ 90 s. M3 gọi `App.mcpCall`.

  - [ ] M6. Thư viện server gợi ý: danh sách có sẵn trong app (tên, mô tả, lệnh `npx`/`uvx`, tham số cần điền, quyền cần cảnh báo) – bấm *Thêm* điền sẵn cấu hình, vẫn qua M2; kiểm tra có Node / Python trên máy, báo thiếu thì hướng dẫn cài
    - **Danh sách (người dùng chốt 2026-10-28, chọn tay – không lấy thẳng từ MCP Registry vì chất lượng không đều):**
      - Bộ server mẫu chính thức `modelcontextprotocol/servers`: **Filesystem** (hỏi thư mục được phép – server stdio dùng cho kiểm tra tay), **Fetch**, **Memory**, **Time**. Tool trả biến môi trường (nếu có) không gợi ý
      - **MarkItDown** (Microsoft, `uvx`): PDF / docx / pptx / xlsx → Markdown, đưa tiếp vào `forEach` / `textMatch` / `askAI`
      - **GitHub MCP chính thức** (HTTP từ xa + PAT qua `{{secret.*}}` làm Bearer – server từ xa dùng cho kiểm tra tay); nhiều tool → ô tìm của M4
      - **Google Workspace** (Gmail / Drive / Sheets) – **bên thứ ba**, ghi rõ trên thẻ; chọn repo còn bảo trì khi làm; liên quan [54](54-dong-bo-cloud.md)
      - **Telegram** (cộng đồng) – gửi thông báo / ảnh lỗi về điện thoại; ghi rõ bên thứ ba
      - Không đưa: Notion (cần OAuth – chưa hỗ trợ), Playwright MCP / chrome-devtools-mcp / Browser Use / MCP computer-use (trùng node web / chính app – AI có hai đường làm cùng việc). Ý học từ các repo này: [hoc-tu-mcp-ngoai.md](../../hoc-tu-mcp-ngoai.md)
    - Mô tả tool của server ngoài cũng là **dữ liệu** như kết quả (nhiều server viết mô tả kiểu ra lệnh "phải gọi tool này trước…"): hiện cho người dùng, không ghép vào chỉ dẫn của AI. Kết nối HTTP bằng SDK Go, không dùng gói `mcp-remote` (đã có CVE nghiêm trọng)
  - [ ] M7. MCP của app + Hướng dẫn: AI soạn được node `mcpTool` (`get_step_types` một dòng + `type=mcpTool` đầy đủ), tool `list_mcp_servers` (chỉ đọc: tên, trạng thái, tool) để AI biết dùng gì; AI **không** thêm / sửa cấu hình server (nó chạy lệnh trên máy); chương *Hướng dẫn* mới (`internal/guide/`) giữ trong ngân sách `budget_test.go`
  - [ ] M8. Cài đặt → tab *MCP server*: danh sách + trạng thái + Thêm / Sửa / Tắt / Xoá + Thư viện; `#demo-mcp` màn mẫu dữ liệu giả
  - Quyết định cần ghi `decisions.md` khi bắt đầu: node tuỳ chỉnh = mẫu của `mcpTool` (không loại node động); AI không sửa cấu hình server; kết quả tool chỉ là dữ liệu.
  - Kiểm tra tay: thêm server Filesystem qua thư viện (stdio) và một server HTTP có Bearer; chạy thử tool đọc không hỏi sau khi duyệt server, tool ghi hỏi; đổi lệnh server → hỏi lại; tạo node *của tôi* rồi mở kịch bản ở máy không có server → node báo thiếu, không lỗi mở file; tắt app khi server đang chạy → không còn tiến trình mồ côi.
  - Xong khi: dùng được tool của ít nhất một server stdio và một server từ xa trong flow, tạo được node tuỳ chỉnh có form sinh từ schema, mọi tool ghi đều qua hộp hỏi.
